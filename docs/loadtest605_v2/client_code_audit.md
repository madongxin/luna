# 605 压测客户端代码审计

日期：2026-10-23。基线提交 `7ce0828`。本轮改动未提交。

`server_to_client_contract.md` 不在客户端仓库里。下面只对照现有 `game.proto` 和已经生成的 `Game.cs`，没有新增协议字段。

## 已经成立的事实

- 每个机器人有自己的 `GameConnection`。读循环和写循环各是一条 `Task.Run`，TCP `NoDelay`。它们不共用一把 C# 锁来收包。
- 真正的玩家和机器人是不同的 TCP 连接。玩家心跳 RTT 大约 100ms，同时机器人心跳 `CLIENT_TIMEOUT`，不能当成同一条连接的结果。
- `CLIENT_TIMEOUT` 在超时回调里判定。判定发生在把结果丢回 Unity 主线程之前。主线程忙不会单独制造这个超时。
- 机器人 `Quiet = true`，成功发送不写同步日志。读循环不在成功路径上做同步日志。
- 移动发送时钟已经是单调钟，同一机器人 Move 最多 1 个在途，错过的节拍不补发。本轮没有重写这套调度。
- Move 等待仍是 2 秒。心跳预算下限仍是 12 秒，上限仍是 20 秒。没有把超时加长来掩盖停顿。
- `GameRequest.Seq` 是 RPC 序号。`ServerPushEnvelope.server_seq` 是推送序号。移动里的 `state_seq` 又是另一件事。界面现在写成「请求seq」和「推送server_seq」，两者不能相减。

## 本轮改动针对的缺口

- 待响应表以前只按 `Seq` 索引。超时先 `TryRemove`，晚到的回包对不上待响应，就被当成推送丢掉，也不计数。
- 连续 Move 超时后，机器人仍用上次确认的坐标接着发。超时不能证明服务器没提交这一步。
- `PushAck` 返回 `ERR_AOI_RESYNC_REQUIRED` 只把错误显示出来，并不等于视野已经恢复。
- `ok=true` 且 AOI 列表为空时，如果当时状态是 `Resyncing`，会把已有实体清掉。2026-10-23 的日志里出现过 `full snapshot ... aoi=0`。
- 压测界面只显示本机玩家所在线。605 人里大约 500 人不在这条线上，界面看不出来。

## 没有改的部分

- 没有改服务器、没有改 `Game.cs`。
- 没有把 2/5/10Hz 当成服务器拒包上限。
- 没有绕过软上限、硬上限或会话检查。
- 没有自动对 `124.222.244.169` 跑 605 人。
