# 分线分布

## 每个机器人记下的权威字段

进图成功后，从 `EnterMapRsp` 记下：

- `map_template_id`
- `map_instance_id`
- `line_no`
- `gamelogic_instance_id`（只用于核对。客户端不按它选路）
- 网关端口（这条 TCP 连的是哪一个）

`EnterMapRsp` 没有 `realm_id`。客户端记下的是这次已被接受的 `EnterMapReq` 里发出去的 realm。快照如果带了 `realm_id`，权威刷新时会改成快照上的值。

## 界面

压测面板列出全部在线机器人，按「实例 + 线 + 端口」分组，不再只显示本机玩家那一条线。

同一模板不是同一个实例。没有跨线 AOI。

状态分成在线、进入中、迁移、断开、未开始。失败会清掉在线，这几项不会叠在同一个人身上。迁移中的重连优先算迁移。

## 容量

1002 的硬上限仍是每线 400、最多 8 线、合计 3200。超过 3200 的波次在开跑前拒绝。

服务器如果没给软上限，界面上的分母仍是回包里的软上限；缺省回落到 100。`101/100` 表示服务器报告的软上限被超过了 1，不是「一张图只能放 100 人」。

溢出时客户端仍发送 `line_no=0`，让服务器分配，不自己编一条线。

## 两种跑法

- 605 人吞吐：允许落在多条线、多个实例上。界面必须把每一组的人数列出来。
- 同实例密视野：只在合法容量里做。客户端不放宽软上限或硬上限。

实机分组结果：**NOT RUN**。上一轮截图里本机线是 101/100、AOI 98，不能当成 605 人都在这一条线上。
