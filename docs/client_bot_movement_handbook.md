# 机器人移动压测手册

客户端只连 Gateway。不要改协议，不要绕过移动校验。这一版没有对生产环境发起 600 人移动压测。

## 现有面板

压测机器人一栏：

- 登录人数、在线分钟、登录间隔、Gateway A/B、密码：和以前一样。
- 移动 Hz：只接受 2、5、10。默认 5。
- 抖动%：默认 10，范围 0 到 50。
- 移动种子：同一个种子加机器人编号，走法可以复现。
- 单一策略：留空表示按比例混合。填写时用这五个名字之一：`Idle`、`LocalWander`、`AoiBoundaryShuttle`、`HotspotGather`、`BidirectionalPatrol`。
- 比例：`停/逛/穿/聚/巡`，默认 `10,35,20,20,15`，加起来必须是 100。

点「集体登录」前会先检查这些值。不合格就不会开这一波。点「导出移动统计」会在 `Logs/` 写下同一次的 json 和 csv。面板上的「计划 / 发出 / 成功」是实测计数，不是目标 Hz。

## 五种走法

分配在进图后按种子和编号固定，中途不改。

- Idle：不发 Move，心跳照常。
- LocalWander：出生点周围 10 到 24 米内选点，走到后停 0 到 2 秒，再选下一点。
- AoiBoundaryShuttle：在出生点附近的 32 米格子边界两侧来回。安全半径只有 24 米，所以不会为了跨过 32 米兴趣半径而走到没核对过的格子上。兴趣半径边界这一项因此标成客户端做不到，不是已经测过。
- HotspotGather：先靠拢到出生点旁的小圈，再绕圈，再散开，然后重复。每个机器人的相位按编号错开。
- BidirectionalPatrol：奇偶编号各走一个方向，默认错开。同步波次要在代码里把 `SyncWave` 打开，而且这一波不能超过 50 人，否则这一波不会启动。

Hz 只决定这个客户端多久发一次。服务器没有 2/5/10Hz 的拒包上限。每一步不能超过 10 米/秒乘上这次和上次 `client_time_ms` 的间隔，机器人自己的步行速度是 5.5 米/秒。高度保持上一次服务器确认的 Y。被拒绝或超时后换一个点，不把同一个点再发一遍。

`MoveRsp.ok=true` 只表示权威坐标已经提交。别人看见的位置大约每 200ms 合并一次。每个观察者最多看见另外 200 个玩家，自己不算。

## 节拍

目标 Hz 用单调时钟。每个机器人同时只有一条 Move 在路上。到点时上一条还没回来，就记一次「忙跳过」，不补发。断线、重连占用、还没进图，记「未就绪」，也不发。心跳和移动是两条循环。

人多的时候不再额外把间隔放成 200 或 400 毫秒。实际发送频率会因为跳过而低于目标，这是预期结果。

## 小规模怎么看

1. 自己先登录进 1002。
2. 人数填 1，Hz 填 5，单一策略填 `LocalWander`，在线 1 分钟。
3. 面板上「发出」应大于 0，「权威确认」应跟着涨。Idle 则「发出」保持 0。权威确认不等于别人已经看见。
4. 导出 json。`actual_send_hz` 用样本时间算，不要把它写成 5。

同图可见要看两边的 `map_instance_id` 相同。1002 单线最多 400 人，一共 8 条线、3200 人。600 人会拆到多条线，线与线之间没有 AOI。10000 人超过总容量，这一波不会启动。这次没有做双开模型同步，CLI-10 记为 NOT RUN。
